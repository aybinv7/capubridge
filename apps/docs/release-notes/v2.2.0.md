# CapuBridge v2.2.0

The first release where an AI agent can drive a full session end to end — find and boot an
emulator, connect a target, record, then query what it recorded — plus a reliability pass on
the two panels people watch the longest: Console and Network.

## Reliable Console and Network capture

Both panels used to bind their CDP listeners from inside the component that displayed them.
That had three consequences: capture only ran while the panel was mounted (switch tabs, lose
events), each of the three console components independently acquired the lease, and a target
that dropped mid-session stayed silently dead until you clicked something.

- **Capture is now app-level.** A single `ObservabilityBootstrap`, mounted once in `App.vue`,
  owns the console lease and the network subscription for the whole app lifetime. Console
  events accumulate whether or not the Console panel is on screen, and `ConsoleOutput`,
  `ConsoleExceptions`, and `ConsoleRepl` are now pure views over that shared store instead of
  three competing lease-holders.
- **Automatic reconnect with backoff.** A failed connect or a rejected `Runtime.enable` /
  `Log.enable` no longer leaves the panel permanently idle — it retries on an exponential
  backoff (500 ms, doubling to a 8 s ceiling) and stops as soon as capture is live again or
  the lease is released.
- **No more cross-target bleed.** Switching targets while a connect was in flight could attach
  the previous target's listeners to the new session, or drop events into the wrong store.
  Binding is now guarded by an in-flight promise per target, and every event handler re-checks
  it is still the active target before writing.
- **Capture state is visible.** Both panels show an explicit `idle` / `connecting` / `live` /
  `error` badge instead of a binary Live/Idle guess, with the failure reason on hover for
  Network. If capture is broken you can now see that it is broken.
- **Network log clears on real navigation.** A top-frame `Page.frameNavigated` clears the log
  when Preserve log is off, matching DevTools behavior.

## AI / MCP — recording, control, and query

The MCP server gained the pieces it was missing to be useful on its own rather than as a
read-only observer.

- **Consult saved recordings.** `list_recordings`, `read_recording`, `read_recording_track`,
  and `read_recording_db` read finalized `.capu` artifacts straight off disk — no device, no
  foreground app. `read_recording_db` scrubs recorded database state to any timeline position,
  either as a per-source change summary or as one source's rows at that point.
- **`query_recording`.** Paging whole tracks did not scale — one raw network track was 2.4M
  characters. This filters a single track (network by status range, URL pattern, resource type
  or method; console by level; any track by time bounds) and, with `correlate_track`, attaches
  another track's events within a window of each match — console errors around a failed
  request, without hand-aligning timestamps. Bounded by construction: compact projections,
  `limit` 50 by default and 200 max, plus `totalMatched` and `truncated` so nothing silently
  overruns the token budget.
- **Frontend bridge and recording control.** Some work only the Vue frontend can do. A
  request/response bridge over Tauri events lets tools drive it: `select_target` connects the
  app's own CDP target, and `start_recording` / `stop_recording` / `get_recording_status`
  control capture, returning the session id and the resulting `.capu` path. Every bridge call
  first brings the CapuBridge window to the foreground, since a minimized WebView can be
  suspended by the OS and would otherwise time out silently.
- **`long_press`.** Faking a long press with a zero-distance swipe was unreliable and, near the
  top of the screen, could hit Android's status-bar gesture zone and pull down the notification
  shade instead. `long_press` uses the same selector/text DOM targeting as `click_element` and
  holds the press for `duration_ms` (default 600) before releasing with a synthetic
  `contextmenu`, which is what touch UIs generally key off.
- **Emulator discovery and launch.** List the AVDs installed on the machine and boot one
  directly from the Device Manager or over MCP — no device required to start working.
- **Sharper tool descriptions.** `input_text` now warns that it silently no-ops when the field
  was focused by `click_element`'s synthetic click (the soft IME never opens — tap to focus
  first, or set the value via `evaluate_js`). `read_network` notes it covers the CDP Network
  domain only, so native HTTP plugins such as `@capacitor/http` are invisible to it and a
  recording is the fallback.

## Fixes

- `vp run desktop#tauri` intermittently died with `EBUSY: resource busy or locked` on
  `app.exe` — the Vite dev server recursively watched the project root, including the Rust
  build output, and racing `cargo` as it rewrote the binary. The dev server now ignores
  `**/src-tauri/target/**`.

## Known limitation

Rust test _execution_ is blocked on the primary development machine by an environmental
`STATUS_ENTRYPOINT_NOT_FOUND` test-binary load failure — confirmed not to be artifact
corruption (a full `cargo clean` and rebuild reproduces it) and not to be this code (the app
itself runs fine, and pre-existing tests fail identically). The tests for the new MCP tools are
written and compile clean; CI runs them.
