# CapuBridge v2.7.0

MCP access is now per client: every agent or tool that connects gets its own named, revocable
token with only the scopes you grant it. Local webview inspection follows child webviews and
redirects instead of losing the page. Recordings carry a new automation track, and replay shows
database writes on the timeline. The automation workbench lands behind the experimental flag.

## MCP client identities

The single shared MCP token is replaced by per-client identities, managed under
**Settings → MCP → Client identities**.

- **One token per client**, each with its own scopes: `read`, `execute`, `authorize`,
  `administer`. Revoke one client without rotating everyone else.
- **The token is shown once**, at creation. It is no longer written into the discovery file.
- **Existing setups keep working.** The old shared token becomes the _Legacy shared principal_
  with exactly the rights it had: read-only, or every scope if "Allow mutations" was on.

## Local webview inspection

- Child webviews are supported, and `about:blank` is allowed as a starting page.
- The debug page is matched by its live URL, so a redirect no longer loses the target.
- Attaching gives up after 10 seconds with a clear error instead of returning nothing.
- OPFS pull works against child webviews.

## Recording and replay

- Recordings gain an **automation track**, and exports include PNG attachments.
- Replay shows **database-write markers** on the timeline and a list of changed tables.
- The performance card says _Not recorded_ when a session has no perf data, instead of an empty
  chart.
- The recording device and producer are shown in replay.

## Automation workbench (experimental)

Manual flows, pluggable agent policies (rules, ARTEMIS, Jev) and a single executor, with secret
redaction on every durable trace and MCP response. The module is **hidden in release builds**
and only appears when built with `VITE_ENABLE_EXPERIMENTAL_FEATURES=true`.

## Known limitations

- **Automation MCP tools are live even though the UI is hidden.** A client with the matching
  scope can list and run flows (`run_flow`, `run_agent_goal`, `task_*` need `authorize`;
  `save_flow`, `delete_flow`, `cancel_run` need `execute`). Grant those scopes deliberately.
- **The Jev policy needs `CAPUBRIDGE_JEV_ENDPOINT`, `CAPUBRIDGE_JEV_API_KEY` and
  `CAPUBRIDGE_JEV_MODEL`.** Without them only Jev fails, with `jev-not-configured`.
- **`.env.local` is read at startup in release builds too**, from the working directory and its
  parents. A shell export still wins over the file.
- **The automation workbench is incomplete.** This release snapshots in-flight CB-M5–M7 work.
- **Theme and updater store tests fail locally on Node 26** (`localStorage` global). CI is
  unaffected.
- **Rust unit tests still do not load on Windows** (`STATUS_ENTRYPOINT_NOT_FOUND`). CI runs them
  on Linux.
