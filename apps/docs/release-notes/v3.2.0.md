# CapuBridge v3.2.0

This PC is now a browser with tabs, and DevTools has a place of its own, with Chrome DevTools
docked beside the screen for pages on This PC and for phones. Phones whose name has spaces no
longer drop off, and pages on This PC can be inspected in released builds.

## This PC is a browser

- **Tabs instead of a target list.** Picking This PC opens its pages as tabs in the Screen
  column, or a New tab when none is open. Data, Network and Elements follow the tab you switch
  to. Closing the open tab moves to its neighbour; closing the last leaves a New tab.
- **Tabs show the page's live title and icon**, and follow in-page navigation. **+** opens a New
  tab, a middle click closes one. The New tab page opens an address and lists recent pages.
- **One toolbar**: reload, address, page size and swap.
  - The address follows the page as it navigates. A path or a URL on the same origin navigates
    the tab; another origin opens its own tab. Alt+Enter opens a new tab.
  - Click reloads, Shift+click reloads past the cache, and a double-click empties the cache and
    reloads.
  - **Responsive** fills the frame and follows it as the column changes. A typed size becomes
    Custom and stays put.
  - **Swap** trades places between the page and the panel beside it.
- **Keys**: Ctrl+T, Ctrl+W, Ctrl+Tab and Ctrl+Shift+Tab work the tabs. On Data › SQLite they stay
  with its query tabs.
- **Tabs come back after a restart** at the address each showed. Only the open one loads.
- The rail hides Device and App while on This PC, and the device manager no longer lists This
  PC's targets: picking This PC opens its tabs.
- The page sits flush in its slot, with no gap or rounded frame around it.
- Inspecting pages on This PC uses WebView2, so it works on Windows only.

## DevTools

- **DevTools is a destination of its own**, beside Elements, with three tabs: Chrome DevTools,
  Vue and React.
- **Chrome DevTools is docked** in the page area, for a page on This PC and for a phone's WebView
  over USB or Wi-Fi. It uses the DevTools bundled with the engine, so it matches it and needs no
  network. Docked DevTools needs WebView2, so it works on Windows only.
- **No second copy of the screen.** DevTools' own screencast is off by default. Settings › Screen
  › "Hide DevTools' own screen" turns it back on.
- **The element picker highlights on our screen**, for pages on This PC and on phones: while
  DevTools is open, the pointer reaches the page as a mouse.
- **Vue and React** are always listed. They show the official panels when the page runs the
  framework, otherwise "This page has no Vue app" (or React) with a check again.
- The inspect action on a target in the device manager opens its Chrome DevTools.

## Data

- **Records can open below the table** instead of beside it, for every database: Settings ›
  Appearance › Data, or the SQLite and IndexedDB header menus.
- An OPFS SQLite database (SAH pool) that the app opened but never wrote to opens as an empty
  database instead of failing as "too small".

## Bring to front

- **One Bring to front, in the title bar.** While the picked app is in the background on the
  phone, an icon beside the context pill brings it forward; its tooltip says why. The duplicate
  buttons over the phone's screen and in the Data tabs are gone.

## Devices

- **A WebView with no page open** shows its app's icon and an open button, instead of failing
  with a technical error when picked. The open button launches the app and scans again.
- The target rows lose their leading dot.

## Fixed

- **Phones whose name has spaces no longer drop off.** A phone connected over mDNS can be listed
  as `adb-<serial>-<id> (2)._adb-tls-connect._tcp`. That one line failed the whole device list,
  so the adb server looked stopped and was restarted every few seconds. Device lists, lookups and
  tracking now read such names, and a running server is never mistaken for a stopped one.
- **Pages on This PC can be inspected in released builds**, which used to answer "Local preview
  CDP access is available only in Windows debug builds". Previews run in a WebView2 environment
  of their own, and CapuBridge's own windows open no debug port in any build. Pages on This PC
  keep their storage in that new environment, so earlier logins and site data are not carried
  over.
- **The window can be dragged by its title bar on macOS**, in the main window and the detached
  screen window. Double-clicking the bar maximizes.
- The title bar's Bring to front can no longer slide under Record session on a narrow window.
