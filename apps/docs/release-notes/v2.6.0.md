# CapuBridge v2.6.0

Network mock rules now belong to a device and target instead of one global list, can be exported
and imported as files, and edit their bodies in a real JSON editor. An AI agent can install rules
and switch intercept mode over MCP without touching the UI. Emulator launch no longer stalls or
lies: it detects an already-running instance, clears crash leftovers, reports the emulator's own
failure line instead of "success", and gains a Stop button for hung instances. IndexedDB
inspection works again on Android WebViews that reject CDP's `requestData`. Every toast now has a
hover Copy button.

## Network mocks are scoped per target

Mock rules and the intercept mode used to be one global list shared across every app you
debugged — switch from one app to another and the first app's rules came along. Rules now live
in a workspace keyed by device and target; the header shows which one you're in. Existing global
rules migrate into the first target workspace you open, so nothing is lost.

- **Export / import a rule** as a `.capubridge-rule.json` file to share a scenario with a
  teammate or keep it with a bug report. Imports are validated field-by-field and rejected with
  a specific message rather than silently producing a broken rule.
- **Response bodies open in a full JSON editor** with pretty-printing, instead of a textarea.
- The CDP interceptor **re-arms on reconnect and on target switch**, not only when you toggle
  the mode — previously a target reconnect left rules armed against a dead session.
- Toggling a rule from the list no longer gets overwritten by an open editor's stale draft.
- Mock server lifecycle moved out of the Network views into app bootstrap, so rules apply even
  if you never opened the Mock tab.

## Drive mocks from an AI agent (MCP)

Two new tools: **`upsert_mock_rule`** and **`set_mock_mode`** (`cdp` / `http` / `off`). Both
require `confirm: true` and are gated behind Mutation access in Settings. An agent can now
reproduce a backend failure by installing a 500 on `/api/sync` and switching interception on,
entirely from the conversation.

## Emulator launch: honest, recoverable, and it boots

Launching an AVD from CapuBridge could report "launch requested" and then nothing — the emulator
had stalled before boot and sat `offline` in ADB indefinitely, while Android Studio insisted it
was running.

- **Root cause fixed:** the launcher inherited the app's process environment, which under the
  dev runner lacks standard Windows variables (`LOCALAPPDATA`, processor info, and more). QEMU
  stalls without them. The emulator now gets a fresh login environment
  (`CreateEnvironmentBlock`), the same one Explorer hands Android Studio. SDK discovery had
  failed for the same reason and now walks every candidate path.
- **Already running → attach, don't relaunch.** A booting or hung instance is detected from the
  emulator's advertisement file or the AVD lock's PID, so you get its serial back instead of the
  emulator's `FATAL: same AVD` refusal.
- **Failures fail.** Emulator output goes to a per-attempt log; if it dies while starting you
  get its own `FATAL` line in the error, not a success toast.
- **Stop button** (and a `stop_emulator` MCP tool) kills a hung instance and clears its locks —
  the recovery path for the `offline` zombie, and it works on emulators CapuBridge didn't
  launch.
- The Emulators panel shows _Starting (pid …)_ → _Running as emulator-5554_ live.

## IndexedDB inspection on Android WebViews

Some Android WebViews reject CDP `IndexedDB.requestData` with `Could not get index`. The explorer
treated that as fatal and rendered an empty table under an error banner — even though the
overview showed the data was there. Any CDP failure now falls back to the in-page reader, and if
that also fails both causes are reported together. The reader also verifies the database exists
on the connected target before opening it, so a read against the wrong target can no longer
create an empty database in another app.

## Also

- **Copy button on every toast** (hover to reveal). Sonner pauses dismissal while you hover, so
  long IPC errors can finally be copied.
- Six source-size governance violations carried over from v2.5.0 are resolved;
  `check:source-size` now reports zero.
- Design direction documents and concept renders for the workbench shell are checked in under
  `docs/design/`.

## Known limitations

- **Emulator launch returns before boot completes** (about 30 seconds later). There is no
  boot-hang detector yet; a future hang still sits `offline` until you press Stop.
- **Stop is a hard kill**, so the next boot is a cold boot.
- **AVD creation is still manual** in Android Studio — no `sdkmanager` / `avdmanager`
  integration.
- **Rust unit tests do not load on Windows** (`STATUS_ENTRYPOINT_NOT_FOUND`). This pre-dates
  this release; CI runs them on Linux.
- **`@capubridge/cdp-protocol` has no `source` export**, so the desktop app consumes `dist/` and
  every edit to that package needs `vp run cdp-protocol#build` before it is visible in dev.
