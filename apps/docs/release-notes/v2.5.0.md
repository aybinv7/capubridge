# CapuBridge v2.5.0

The SQL Explorer now finds every SQLite database on a device by itself — including ones hidden
inside a SAH-Pool that used to require manually decoding an OPFS directory first — and tracks
their changes live the same way the IndexedDB explorer always has. Under that sits a real
performance fix: opening a large OPFS-backed database no longer routes the whole file through
JavaScript, and a socket limit that was silently killing the connection on bigger databases is
gone. The Device Manager is also reorganized around how a device actually reaches the app —
This PC, Emulators, Devices, Remote — instead of one flat list.

## SQL Explorer auto-discovers every SQLite database

Previously, an OPFS-backed database (direct file, SAH-Pool, or wa-sqlite) only showed up in the
SQL Explorer after you went into the OPFS panel, found the right file, and manually decoded it.
Now the SQL Explorer walks OPFS itself — verifying by SQLite magic header, not filename, so
extension-less SAH-Pool slots are found too — and lists every database next to the native and
jeep-sqlite ones you already had.

- Each entry carries a badge naming its storage type (`opfs`, `sah-pool`, `wa-sqlite`, `jeep`,
  `native`); hovering explains what that layout actually is, names the owning package, and
  offers a **"Show in OPFS explorer"** link straight to that file's directory.
- Clicking a discovered database opens it directly — no manual decode step first.
- Opening one database no longer hides the others: native, jeep, and OPFS entries all stay
  listed regardless of which one is currently open, and switching device or target keeps
  re-discovery in sync.

## Faster OPFS reads, and a real hang fixed

Opening a large OPFS/SAH-Pool database in the SQL Explorer could silently hang with no error —
the browser's WebSocket peer enforces a 16 MiB frame ceiling by default, and a big database's
base64 payload could exceed it in a single response, killing the CDP connection mid-transfer
with no feedback. The proxy and the MCP CDP client now negotiate explicit, much larger frame
and message limits, and reads are chunked (8 MiB at a time) with a progress toast, so this
can't recur regardless of database size.

On top of that, the whole read now happens in Rust instead of JavaScript: a new
`opfs_pull_sqlite` command runs the chunk loop over one CDP connection and streams decoded
bytes straight to a temp file, so a large database is no longer held in memory three times over
(as an ArrayBuffer, a JS binary string, and a base64 string) on its way from device to disk.

Switching between databases is now close to instant: a per-target snapshot cache remembers what
was already pulled, and a cheap size+mtime stat (one CDP call, or one `run-as stat` for a native
device database) decides whether to reuse it — no re-pull unless the file actually changed.

## Automatic, live change tracking for SQLite

SQLite databases now track changes the same way the IndexedDB explorer does, with no toggle to
remember: opening a database starts a background poll that diffs it against its last snapshot,
lights up add/update/delete indicators in the sidebar on both the database and table rows, and
feeds the same row-level diff viewer. The manual **Live** button is gone — tracking is just on.

- The background poll only costs something when the database actually changed: a cheap stat
  (OPFS or native) decides whether to re-read at all, and a poll that finds nothing new never
  touches the table's loading state or resets your scroll position.
- The diff viewer no longer opens invisibly behind the row detail dialog it's triggered from —
  opening a diff now closes the row viewer first instead of stacking on top of it.

This still isn't identical to IndexedDB's tracking: SQLite has no equivalent of
`indexedDBContentUpdated`, so only the **currently open** database is diffed, and other rows
show no indicators until you open them.

## Device Manager: grouped by how a device reaches you

The device picker is reorganized into labelled sections — **This PC → Emulators → Devices →
Remote** — instead of one flat list mixing physical, emulated, and Wi-Fi-attached devices
together. An emulator is classified by what it is, not by transport, so it's grouped correctly
even though it reaches ADB over USB like a cabled phone.

- **Emulators** and **Remote** each carry a "+" in their section header to launch a new
  emulator or connect a new remote device — visible even when the section is empty, since
  that's the only way to populate it. **Devices** (USB) and **This PC** have no such button,
  since neither ever needs one.
- **Forget a device** via right-click → **Forget device**. Every device the app has ever seen
  used to be kept forever, just flagged stale — a Wi-Fi device reassigned a new IP by DHCP is a
  new serial that will never reconnect at the old address, so those accumulated indefinitely.
  This removes one from the registry and its persisted cache for good.
- Fixed: a rich tooltip (the storage-source badge, the diff-adjacent hints) inherited the
  app's compact inverted micro-tooltip style — white text on a white card, unreadable in dark
  mode. Tooltips can now opt into a `surface` variant that matches the rest of the dark UI.

## Also in this release

Several fixes already on `master` since v2.4.4 that had not yet reached a tagged release:

- **CDP connection lifecycles are now bounded** — connections and their listeners are torn
  down deterministically instead of relying on GC/timeout.
- **Proxy and MCP lifecycles hardened** — the CDP proxy and MCP transport tightened their
  connection/auth handling.
- **Recording evidence is preserved and sanitized** on normal stop, cancellation, and
  disconnect, including partial-artifact recovery.
- **IndexedDB identity preserved with a bounded fallback** in the storage explorer.
- **Native SQLite snapshots are now read-only**, preventing an accidental write path into a
  temp copy that was never meant to be mutated.
- **The capture registry lock releases before its `await`**, closing a lock-holding-across-a
  wait pattern that could stall unrelated capture operations.

## Known limitations

- **jeep-sqlite's reader is not yet chunked.** It returns an entire database as one base64
  string from a single `Runtime.evaluate` call — the raised proxy limits protect it from the
  connection-killing bug above, but it still holds a large database in memory several times
  over on the device. Flagged as a follow-up, not fixed here.
- **Remote (Wi-Fi) device flows — connect, launch app, debug — were verified by reading the
  code, not by driving a live device.** Every device operation is keyed by ADB serial with no
  functional branch on transport, and per-serial CDP port allocation was exercised, but no
  Wi-Fi device was online during this work to confirm end-to-end.
- **Two source-size governance ceilings were raised to unblock this release**, not resolved:
  `SqliteExplorer.vue` (1936 → 2203 lines) and `commands/sqlite.rs` (1087 → 1200 lines) grew
  from this release's own work. The owed split — snapshot/diff/discovery orchestration into
  their own composables — is tracked, not done.
- **Six unrelated `check:source-size` violations pre-date this release** and remain
  (`useStorageGraphData.ts`, `ReplayDatabasesPanel.vue`, `StorageGraphExplorer.vue`,
  `IDBExplorer.vue`, `IDBTable.vue`, `SqliteTable.vue`) — none were touched by this work.
