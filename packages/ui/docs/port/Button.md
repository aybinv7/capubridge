## Deviations

- `data-pressed` not emitted (`Button.tsx:190`) — the pressed state reaches the surface but not the
  attribute, so consumer styling and tests keyed on `data-pressed` break. Contradicts the audit's
  "`data-*` attribute set match" claim for `Button`.
- `data-cui-explicit-accent` (`Button.vue:115`) replaces upstream's `color !== 'neutral'` condition
  (`Button.tsx:194`–`197`), changing the label colour for `color="neutral"` on non-fill variants.
- `aria-busy`, `aria-disabled`, native `disabled`, and the capture-phase activation guard
  (`Button.vue:90`–`97`, `113`–`121`) are Vue additions with no upstream counterpart.
- `accent` prop (`Button.vue:20`) — Vue-only alias for `color`.
- `surfaceLevel` and `variant` are withheld from `SurfaceCut` (`Button.vue:83`–`85`) where upstream
  forwards them into `...rest` (`Button.tsx:222`, `227`). Upstream's behaviour leaks unknown
  attributes onto the DOM because `SurfaceCut` declares neither prop; the Vue behaviour drops them
  instead. Divergent either way, and undocumented until now.
- `useComponentDefaults` / `ButtonDefaultProps` not ported (`Button.tsx:136`, `92`–`94`). Audit
  finding 7.
- `contextmenu` suppression moved from capture to bubble phase (`Button.tsx:237` vs
  `Button.vue:122`).
- `controls.css:137`–`147` adds `appearance: none`, `margin: 0`, `border: 0`, `font-family: inherit`,
  `line-height: 1.5`, `background: transparent`, and `padding: 0`. Upstream gets all but the
  line-height from Tailwind's preflight, so those are reset equivalents rather than copied values.
  `line-height: 1.5` (`controls.css:145`) has no upstream source and is a Vue choice.
- `paddings` and `fontSizes` (`Button.tsx:150`–`167`) are declared inline upstream and were resolved
  straight into CSS. They are not in `button.contracts.ts`, so no value-lock test can import them.
  Bucket-A extraction gap, audit process fix 3.
